# 의동이 PICK USB 제출 패키지 결과

## 데이터와 구현 범위

사용자가 기존 CSV로 진행하고 가상 표시를 유지하도록 승인했습니다. 관광 조사 후보 35개와 가상 업소 30개(맛집18·카페12)를 사용합니다. 원본 CSV·엑셀은 `data`에, 변환된 감사용 JSON과 인코딩·헤더·결측 분석 결과도 동봉했습니다. 주최 측이 제공한 실제 CSV로 확인된 자료라고 설명하지 않습니다.

기존 온라인 앱 소스의 디자인·검색·필터·시간순 추천·추천 이유·요약·가상 표시를 재사용했습니다. USB판에는 검색 결과에 맞춰 갱신되는 분류·권역·가상 업소 예산의 데이터 차트 3개를 추가했습니다. 지표는 레코드 수이며 실제 방문·매출 성과가 아닙니다.

## 실행 A: Windows BAT + 포터블 Node

- `실행하기.bat`는 `%~dp0` 상대경로와 CRLF를 사용하며 사용자 명령 입력과 npm 설치가 없습니다.
- x64와 ARM64 실행 파일을 동봉하고 PROCESSOR_ARCHITECTURE / PROCESSOR_ARCHITEW6432를 읽어 선택합니다. 32비트 Windows는 지원하지 않습니다.
- `server/launcher.cjs`는 내장 모듈만 사용합니다. 127.0.0.1의 OS 할당 빈 포트에서 시작해 헬스체크 후 Windows 기본 브라우저 열기를 시도합니다.
- 포트 충돌을 피하고, 누락 파일/시작 오류/브라우저 열기 오류를 구분하여 표시합니다.
- 웹서버는 index와 assets만 제공하며 source·node·data 원본은 HTTP로 공개하지 않습니다.
- USB에 설정·로그·설치 파일을 쓰지 않습니다. 창을 닫으면 서버가 종료되는 구성이며 실제 Windows 실행은 아래 미검증 범위입니다.

## 실행 B: index.html

- 앱의 ES 모듈을 esbuild IIFE classic script로 번들했습니다. 데이터 로더만 빌드 사본에서 내장 데이터 반환으로 대체해 온라인 원본 로더를 수정하지 않았습니다.
- CSV/JSON 런타임 fetch, 동적 모듈 import, 외부 라이브러리 CDN이 없습니다. 이미지·CSS·JS는 상대경로입니다.
- Noto CJK KR 글꼴은 SIL OFL 라이선스와 함께 로컬 파일 및 CSS data URI로 동봉했습니다. 파일 글꼴 CORS 제약을 피하고 별도 폰트 설치가 필요 없도록 구성했습니다.
- 브라우저의 file:// 주소 자체 차단, 스크립트 실행 차단은 우회하지 않습니다. 클립보드가 제한되면 기존 수동 텍스트 복사를 제공합니다.
- 외부 공식 사이트·지도는 인터넷이 필요하며 오프라인 클릭 시 안내합니다. 핵심 기능은 외부 API에 의존하지 않습니다.

## 런타임 무결성

Node.js v24.22.1 Windows x64·ARM64 공식 ZIP을 nodejs.org에서 HTTPS로 내려받아 공식 SHASUMS256.txt와 SHA-256을 대조했습니다. ZIP에서 추출한 node.exe 파일의 해시·PE 기계 형식도 검사했습니다. `node/검증내역.json`, `node/SHASUMS256.txt`와 각 LICENSE를 동봉합니다. Windows용 exe를 Linux에서 실행했다고 주장하지 않습니다. x64 PE의 DLL 의존 목록은 Windows 기본 라이브러리로 확인했지만, 심사위원 PC에서의 실제 실행을 대체하는 검증은 아닙니다.

## 실제 테스트 결과

자세한 개별 결과는 `검증결과.json`에 있습니다.

| 패키지 HTML을 로컬 제공 후 인터넷 차단 | 통과: 65개 표시, 맛집18·카페12 검색, 예산 필터, 빈 검색, 차트 갱신, 추천, 체크 이유, 요약, 복사 또는 대체, 모바일 |

| CSV 한글 인코딩·필드 구조 | 통과: CSV 2개 UTF-8 BOM, 30행24열/35행14열, 대체문자 없음 |
| 실제 Windows BAT 더블클릭 | 미검증: 이 환경은 Linux이며 Windows/Wine 없음 |

| Windows 기본 브라우저 자동 열기 | 미검증: Windows 전용 cmd start 경로를 정적으로 준비 |

`file://`에 맞춘 코드 구조는 정적 검사했지만 관리 브라우저에서 실제 직접 열기 성공으로 보고하지 않습니다. 이 한계 때문에 심사위원 Windows PC에서 사전 확인이 필요합니다. 파일 열기가 차단되면 BAT 방식, BAT도 기관 보안 정책으로 차단되면 PDF·화면 캡처가 가장 안전한 대안입니다.

## PPT·PDF 설명

5분·5장: 문제 정의 → 서비스 소개 → CSV 데이터 활용 → 실제 화면 → 군민 혜택. PPTX는 편집 가능한 텍스트·도형과 발표자 노트, PDF는 같은 5장입니다. 원본 화면 PNG와 약 5분 분량의 대본도 포함합니다. 기대효과는 실제 효과 측정과 구분하고, 외부 AI·실시간 지도·예약을 구현했다고 설명하지 않습니다. PowerPoint 없는 PC에서는 PDF를 기본 브라우저로 열 수 있습니다. 실제 발화 시간은 발표자가 연습하여 조정해야 합니다.

## 개발자 재생성

심사위원 실행에는 아래 설치가 필요하지 않습니다. 빌드용 Linux 개발 환경에서 Python(폰트·PPT 라이브러리), Node/npm, esbuild, Chromium·Playwright, LibreOffice가 필요합니다.

1. `python3 scripts/prepare-usb-node.py --cache ../usb-build-cache`
2. `NPM_CONFIG_CACHE=/tmp/uidongi-npm-cache python3 scripts/build-usb.py --output ../USB_최종제출 --node-cache ../usb-build-cache`
3. `python3 scripts/test-usb-package.py ../USB_최종제출` (실제 환경에 따라 미검증 항목을 그대로 기록)
4. `python3 scripts/create-usb-presentation.py ../USB_최종제출`
5. LibreOffice headless로 PPTX를 PDF로 변환하고 5페이지·한글·잘림을 확인합니다.
6. 원본 `source`와 최종 체크섬을 갱신하고 폴더 전체를 ZIP으로 묶습니다.

주어진 대상 폴더가 이미 있으면 빌드 도구는 덮어쓰지 않습니다. 원본 웹앱 실행은 `npm start`, 검사·빌드는 `npm run build`입니다. 원본 온라인 배포 방식에는 USB 런타임이 필요하지 않습니다.
