# 의동이 PICK: 시간순 맞춤형 여행 일정 카드 결과

## 프로젝트 분석

프로젝트는 React/Next.js/TypeScript가 아닌 순수 JavaScript ES 모듈 정적 웹앱입니다. 프레임워크를 교체하지 않고 기존 구조를 유지했습니다. 추천 버튼은 app.js의 form submit → recommend → planner.buildTrip → scheduler.planDay이며, 입력 상태는 동일한 state와 readControls/syncControls를 재사용합니다. CSV는 기존 24개 한글 필드의 가상 업소 CSV를 dining-import.js로 JSON 변환한 뒤 로드하며, USB는 빌드 시 같은 자료를 JavaScript에 내장합니다. 관광 후보35·가상맛집18·가상카페12, CSV/JSON 레코드·필드명은 바꾸지 않았습니다. 별도 주최 측 CSV 대신 기존 자료를 가상 표시로 사용한다는 이전 승인을 유지합니다.

## 변경 파일

- public/itinerary-cards.js (신규): 유형·지도·금액·요약 모델, 개별 카드·연결선·날짜별 타임라인 DOM
- public/meal-times.js (신규): 점심11:30~14:00·저녁17:00~20:00의 일정 선호 구간
- public/app.js: 기존 결과를 새 카드 렌더러에 연결, 날짜 선택·조건 수정·재추천, 복사에 비용·제외 정보 추가
- public/index.html / style.css: 요약·액션·접는 장소 목록·주황/초록/갈색/파랑 유형 카드·모바일 스타일
- public/scheduler.js: 기존 시간·운영·이동 검사 유지, 시간 허용 시 별도 점심·저녁 장소를 배치
- public/recommendation-reasons.js: 실제 예산·권역 일치 및 저녁 배치 이유, 가상/미확인 구분
- itinerary-cards.test.js (신규): 유형, 주소/좌표, 가상 지도 차단, 비용 합산, 조건 이유, 점심·저녁, 요약 시간 검증
- scripts/test-usb-package.py / create-usb-presentation.py: 새 목록 접기와 카드 캡처·발표 내용에 맞춰 USB 검증·자료 갱신
- package.json / README.md / 본 문서 / packaging의 안내·검증 문서: 버전·실행·제한·최신 검증 범위

## 실제 구현

장소별 방문 번호, 시작/종료, 유형 색상·아이콘, 장소명, 주소 또는 가상 읍면/미확인 위치, 체류분, 등록 금액, 의동이가 추천한 이유와 지도 버튼을 카드로 표시합니다. 이동과 대기는 별도 연결 구간입니다. 여러 날은 전체·날짜별 버튼으로 확인하며 전체 장소 목록·기존 검색·필터·USB 차트는 접기·펼치기 안에 보존했습니다. 결과 최상단에는 기간·시각·등록된 1인 금액과 기존 방문/체류/이동/상권 지표를 표시합니다. 빈 결과에는 완화할 조건과 수정 버튼을 제공합니다.

예산 합계는 CSV의 1인 예산(가상) 또는 명시적인 per-person 금액만 포함합니다. 단위 미확인 금액, 미등록 장소, 교통·숙박·추가 주문·개인 소비는 제외하고 인원수를 곱하지 않습니다. 0원과 미등록은 구분합니다. 이 합계는 실제 총여행비나 예산 보장을 뜻하지 않습니다.

지도는 가상이 아닌 자료의 주소 또는 유효한 위도/경도 객체가 있을 때 외부 지도 검색 URL을 생성합니다. API 키가 필요하지 않습니다. 현재 데이터의 관광 후보는 주소·좌표 미확인이고 업소는 가상이므로 카드 지도는 비활성으로 안내합니다. 이름만으로 실제 위치를 확정하거나 가상 좌표를 생성하지 않았습니다.

## 알고리즘·시간·이유

기존 일수별 활동시간 분배, 동행·관심사·권역·실내외·업소 예산·반려견·주차 필터, 영업시간·휴무·브레이크타임, 중복 방지, 후보 경로 탐색을 유지합니다. 관심사 범위가 같은 긴 일정에서는 점심·저녁 구간 충족을 소폭 우선합니다. 같은 식사 구간을 중복 배치하거나 같은 업소를 반복하지 않으며 시간이 맞지 않으면 두 끼를 강제로 넣지 않습니다. 카페는 하루1곳, 관광 전후 휴식 선호를 유지합니다.

등록된 이동값/사용자 입력 여유는 한 번만 더하고, 체류·대기와 합산해 날짜별 마감을 넘는 후보를 제외합니다. 이동 근거가 없으면 null/확인 필요로 남기고 이후 시각은 최소 시각의 임시 일정입니다. 실제 종료·영업 충족을 보장하지 않습니다. 첫 방문지 도착 전·숙박·날짜 간 이동은 기존대로 제외합니다.

추천 이유는 선택 동행과 audiences, 관심사와 categories, 예산과 1인 price, 권역과 region, 실제 배치된 점심/저녁 시간만 사용합니다. 가상 금액·배치임을 표시하고 미확인 이동 이후에는 점심/저녁·전체시간 충족을 확정 이유로 사용하지 않습니다. 새 AI·최단 경로를 구현했다고 표현하지 않았습니다.

## 검증과 한계

최신 자동 테스트·브라우저·USB 결과는 제출 폴더의 검증결과.json을 기준으로 보고합니다. 실제 Windows BAT/Node 미설치 PC/드라이브 문자 변경 및 file:// 직접 열기는 이 Linux 관리 환경에서 미검증입니다. 관리 Chromium의 file:// 차단을 우회하지 않았습니다. 인터넷 차단 후 로컬 서버 방식의 검색·필터·차트·카드·이유·복사·모바일 검증과 실제 Windows 성공 주장은 구분합니다.

실제 주소가 없는 데이터의 지도는 비활성 상태를 검증하고, 테스트 주소/좌표의 외부 URL 생성만 검증합니다. 외부 지도 사이트의 실제 응답이나 경로·교통 데이터는 검증 범위가 아닙니다. 실제 운영/가격/예약은 아직 연결하지 않았습니다.

## 실행·빌드

- 개발: Node.js 20 이상에서 npm start → http://localhost:3000
- 검사·정적 빌드: npm run build (데이터 검사 + 자동 테스트), 산출물 public
- USB: 포함된 실행하기.bat / 보조 index.html. 심사위원에게 npm·VS Code 설치를 요구하지 않습니다.
- 발표: 제출 폴더의 5장 PPTX/PDF·대본을 사용합니다. 실제 새 카드 화면을 캡처해 갱신합니다.
